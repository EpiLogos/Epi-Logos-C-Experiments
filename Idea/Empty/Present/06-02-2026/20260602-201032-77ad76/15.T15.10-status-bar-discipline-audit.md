## Status-Bar Surface

The Theia status bar now has one owning contribution: `KernelBridgeStatusBarContribution`.

Canonical entries:

| Entry | Status-bar id | State source |
| --- | --- | --- |
| profile-tick state | `pratibimba.status.profileTickState` | `KernelBridgeAPI.cachedProfile` |
| day-now anchor | `pratibimba.status.dayNowAnchor` | `PratibimbaSessionStateService.state.dayNow` |
| session id | `pratibimba.status.sessionId` | `PratibimbaSessionStateService.state.sessionKey` |
| gateway readiness | `pratibimba.status.gatewayReadiness` | `KernelBridgeAPI.connectionStatus` |
| profile generation | `pratibimba.status.profileGeneration` | bridge profile, session state, then connection status |
| active coordinate | `pratibimba.status.activeCoordinate` | `PratibimbaSessionStateService.state.selectedCoordinate` |

No layout/mode indicator remains bound as a status-bar contribution. Layout switching remains available through the existing command/menu membrane, but it is not status-bar real estate.

## Day-Now And Session Ownership

The day-now anchor is normalised by `normaliseDayNowAnchor(...)` to the DR-M4-1 form:

```text
Idea/Empty/Present/{day_id}/
```

Browser-source audit found no widget reading `Idea/Empty/Present`, `nowPath`, or filesystem day/session paths directly. `SESSION_STATE_SERVICE` is imported by status-bar/runtime services and command dispatch surfaces, not by day/session-owning widgets. Widgets that display day-now or session values receive them as evidence or intent payloads; they do not own the anchor thread.
