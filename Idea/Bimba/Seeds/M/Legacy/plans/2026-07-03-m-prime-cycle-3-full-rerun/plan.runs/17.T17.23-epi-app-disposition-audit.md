# 17.T17.23 `epi-app` Disposition Audit

## Result: Retain as Deprecated Migration Source / Parity Reference

`Body/S/S3/epi-app` must not yet be moved, deleted, or archived. The current
S3 canon already records the correct deprecated status and requires proof that
no invariant remains uniquely represented before removal. That proof is not
available in the current tree.

## Current Canonical Status

- `[[S3-SPEC]]` states that `epi-app` is deprecated legacy parity material and
  that M' shell authority belongs to `Body/M/epi-theia`.
- `[[S3-SPEC]]` explicitly permits removal only under a named follow-up after
  proving there is no uniquely tested S3 invariant.
- `Body/S/S3/epi-app/AGENTS.md` is consistent with that boundary: retiring,
  no new feature work, preserve any still-unique behavior before archival.

## Archival Blockers

- `Body/M/epi-theia/extensions/MIGRATION-SOURCES.md` still names many
  `epi-app` components and main-process files as migration sources.
- The Theia `omnipanel-shell` documentation and source provenance still cite
  the legacy OmniPanel tree as the wholesale-port source.
- The legacy suite cannot be executed in this checkout: `npm test` fails
  before test discovery because `vitest` is not installed and
  `node_modules/` is absent.
- The inspected `gateway-parity.test.ts` is helper-level and includes mocked
  gateway requests. It is not sufficient evidence that its claimed S3
  invariants have been preserved by a live gateway/carrier path.

## No Change Required Here

The requested S3-SPEC wording correction is already present. Moving the
directory without first retiring the documented Theia migration-source links
and replacing any required behavior with real gateway/carrier coverage would
be a destructive, unverified change. This tranche therefore retains the
existing compatibility disposition and records the prerequisites for a later
archival tranche.

External review remains Claude-owned. This audit is not a verification or
done-closure receipt.
