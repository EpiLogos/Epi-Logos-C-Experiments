# 15.T15.9 Tick Choreography Carrier Audit

## Verified: Shared App Clock and Deterministic Display Scrub

The active carrier has one real modulation engine that ingests the profile bus,
keeps a bounded record history, freezes a viewed record while paused, and
returns deterministically to the same rendered state when stepped back and
forward. This is exercised through Chromium against a spawned real gateway.

`src/engine/modulation/engine.ts` is the shared record/clock surface; the
visual-regression e2e test observes the resulting canvas rather than a mocked
rendering path.

## Executed Evidence

`pnpm playwright test tests/e2e/visual-regression.spec.ts --grep "tick choreography"`
passed: 1 Chromium test against the spawned gateway and real filesystem vault.
It proved all of the following at the rendered-pixel level:

- paused display remains pixel-static while profile ingestion continues;
- stepping back changes the rendered record;
- stepping forward to the same record reproduces the prior pixels; and
- resume leaves the frozen frame and continues the choreography.

## Not Proven for the M1 Played-Torus Surface

The `PlayedTorusPane` applies only the newest `anandaVortex` snapshot directly
to its local Three.js scene. It is not registered as a modulation carrier and
does not consume a profile-record interpolation fraction. Consequently the
evidence above establishes the shared engine's tick/display-scrub law, but not
`quat_slerp` or six-matrix/DR-streamline choreography inside the M1 K2 surface.

That missing proof is coupled to the T15.8 projection gap: current profile
payloads expose one active cell and ring values, rather than the full six
matrix layers and ordered streamline payload needed for honest choreography.
The frontend must not reconstruct them from local LUTs.

## Scope

No code change was made. This is an audit-only tranche: app-level clock truth
is verified; the M1 full-fidelity subclaim remains awaiting a backend-owned
render payload and an explicit played-torus modulation-carrier integration.

External review remains Claude-owned. This audit is not a verification or
done-closure receipt.
