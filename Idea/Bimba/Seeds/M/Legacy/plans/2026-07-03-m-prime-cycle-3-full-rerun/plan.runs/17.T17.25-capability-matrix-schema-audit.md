# 17.T17.25 Capability Matrix Schema Audit

## Result: Schema Co-Located, Consumer Integration Incomplete

`Body/S/S4/plugins/pleroma/capability-matrix.schema.ts` already exists beside
the authoritative `capability-matrix.json` and defines the TypeBox matrix and
M5-4 evidence-bridge schemas.

The consumer-integration claim is not yet true:

- Anima's `extension/capabilities.ts` parses JSON and applies only an ad hoc
  `Array.isArray(parsed.skills)` guard; it does not validate with
  `CapabilityMatrixSchema`.
- The active Pratibimba app imports the JSON directly for the evidence-field
  parity test; it does not import or validate through the co-located schema.
- Existing Anima registry tests also read the JSON directly.

The schema is therefore correctly resident but not yet the shared runtime
validator required by the tranche. Moving or duplicating it would not close
that gap; the follow-up must decide an active-carrier-compatible shared schema
distribution/import boundary and then wire every declared consumer through it.

## Evidence

`python3 -m pytest Body/S/S4/plugins/pleroma/tests/test_capability_matrix.py -q`
passed: 18 tests. This proves the current matrix contract, not the missing
TypeBox consumer-validation integration.

External review remains Claude-owned. This audit is not a verification or
done-closure receipt.
