## 1. Why cold-start exists

The matheme `0/1 = 4+2 = 5→0` operates at the threshold of first encounter: cold-start IS the `0` (ground unfolding). A new user with no PASU, no first profile-tick fired, no day-now anchor lit, facing a `daily-0-1` layout of widgets all reading `bridge_unavailable`, would experience the system as broken. The cold-start orchestration IS the legibility of the substrate at the threshold. It sequences activation and renders each stage's state so "not yet ready" reads as *unfolding*, never as *broken*.

## 2. The six-stage sequence (LAW — source §"Cold-Start Sequence", `:32-39`)

Each stage consumes a readiness-ledger entry and renders its own splash sub-state. Stage state is one of `pending | active | ready | blocked` (source `:55`).

| # | Stage | Consumes (readiness ledger / RPC) | Ready-transition |
|---|---|---|---|
| 1 | **Bridge initialization** | the shared bridge adapter binds | `bridge_unavailable` → `pending_first_tick` |
| 2 | **Kernel-bridge subscription** | kernel-bridge subscribes to portal-core / S2 / S3 | `bridge_unavailable` reason cleared |
| 3 | **S2/S3 substrate handshake** | S2 graph reachable + S3 gateway reachable | `s2_graph_blocked` AND `s3_subscription_blocked` cleared |
| 4 | **First profile-tick** | `MathemeHarmonicProfile` first tick fires | `pending_first_tick` → `ready_public_current` |
| 5 | **Day-now anchor** | `vault.day.ensure` RPC; status-bar day-now lights | today's day folder ensured |
| 6 | **Optional kairos refresh** | gated by FR-3 `KAIROS_ENABLED`; Mercurius (19.12) fires the kerykeion adapter | `M4_Temporal_Now.planet_degrees[10]` populated |

**Ordering invariant:** stage N does not enter `active` until stage N-1 is `ready` (deterministic advance). Stage 6 is *optional* — a disabled kairos does not block completion. Stage 4's `ready` is also the PASU-absence probe point (32.2 orchestration): fire `nara.pasu.show`; on `not_found`, suspend stage 6 and dispatch the identity wizard (25.4) before continuing.

## 3. The splash contract (LAW — source Tranche 32.1, `:57-59`)

A cold-start splash surface mounted as an **overlay** — backdrop is click-through (`pointer-events: none`); only the splash card is interactive.

- **Header:** the matheme glyph `0/1 = 4+2 = 5→0` (WC-OB-19) — structural law made visible, not decoration.
- **Six rows**, one per stage, each bound to that stage's state stream. Per-row UI: stage label · state pill · reason (when `blocked`) · retry button (when `blocked`) · diagnostic deep-link (when `blocked`, via 32.7).
- **Per-step render grammar** (consumes 32.5): `active` = shimmer; `ready` = checkmark; `blocked` = state badge per the readiness-state-grammar mapping (e.g. `s3_subscription_blocked` → "S3 gateway down" overlay + retry + status link).
- **Dismiss semantics:** auto-dismiss when all six stages reach `ready`; **manual dismiss available on the FIRST `ready` reached** — so a blocked stage never traps the user.

## 4. Post-cold-start handoff (source `:41`)

After cold-start: identity wizard (32.2) if PASU absent → post-identity walkthrough (32.3) → Anuttara grounding (M0 empty state, Track 21) OR first-session affordance (32.11). Reset (32.12) clears the onboarding-completion ledger back to empty, returning the user to cold-start — the `5→0` Möbius return.

## 7. Acceptance for the carrier implementation (retargeted from source `:63`)

When the carrier cold-start surface is built, it is accepted when:
1. The orchestrator advances the six stages **deterministically** against a synthetic readiness-ledger stream (stage N `active` only after N-1 `ready`).
2. The splash renders six rows bound to the stage streams, with the matheme glyph header present.
3. **Non-blocking dismiss:** the user can dismiss on the first `ready` even while other stages are `blocked`.
4. A `blocked` stage renders reason + retry + diagnostic deep-link (32.7) per the readiness-state grammar (32.5).
5. Stage 4 `ready` fires the PASU-absence probe and, on `not_found`, suspends stage 6 and hands off to the identity wizard (32.2 / 25.4).
6. Proof is real app-flow (UF/app-ui-flow per Track 00), not a jsdom mock.
