# Bimba graph backup & restore runbook

**Tranche:** `54.T54.05` — "Backups, so this is a five-minute inconvenience next time"
**Installed:** 2026-07-29 · **Host:** admin@macOS · **Neo4j:** 5.26.21 (Community)
**Repo copy:** `.codex/scripts/neo4j-volume-backup.sh` · **Deployed copy:** `~/epi-backups/neo4j-volume-backup.sh`
**A copy of this file lives next to the backups at `~/epi-backups/neo4j/RESTORE-RUNBOOK.md`.**

---

## 0. Why this exists

On **2026-07-28 ~19:42 BST** an unscoped `cargo test -- --ignored` ran
`MATCH (n:Bimba) DETACH DELETE n` against the live development Neo4j and destroyed
~2,800 enriched nodes. Both recovery paths were already gone before anyone looked:

- the APFS local snapshot was purged when 52 GB was freed on a 97 %-full disk;
- **`Docker.raw` is `[Excluded]` from Time Machine by default**, so TM held nothing
  of the graph volume.

**There was no backup. That — not the test that fired — is the root cause of the
severity.** Track 54 spent four tranches reconstructing state from the transaction
log. This runbook is so that never has to happen again.

## 1. What is backed up, and where

| | |
|---|---|
| Source | docker volume `epi-logoscexperiments_neo4j-data` (the `epi-neo4j` container's `/data`) |
| Destination | `~/epi-backups/neo4j/` — **outside `Docker.raw`**, inside `$HOME` |
| Time Machine | `tmutil isexcluded ~/epi-backups/neo4j` → **`[Included]`** (verified 2026-07-29) |
| Naming | `epi-neo4j-data-YYYYMMDDTHHMMSSZ.tar.gz` + a `.sha256` sidecar |
| Contents | the whole volume: `databases/`, `transactions/`, `server_id`, `backups/` |
| Size | ~71 MiB compressed from ~550 MiB on disk; ~9 s per run |
| Retention | **7 days**, enforced on every run; the newest snapshot is never deleted |
| Log | `~/epi-backups/neo4j/backup.log` |

`~/bimba-forensic/` holds hand-curated forensic evidence from the incident. It is
**not** under this script's retention and must never be pointed at by it.

## 4. RESTORE — the five-minute path

**Never restore over the live volume as a first move.** Restore into a throwaway
on a non-7687 port, confirm the counts, and only then decide.

```bash
BK=$(ls -1 ~/epi-backups/neo4j/epi-neo4j-data-*.tar.gz | tail -1)   # or name one

# 1. integrity
cd ~/epi-backups/neo4j && shasum -a 256 -c "$(basename "$BK").sha256"

# 2. unpack into a scratch data dir
RESTORE=~/epi-backups/.restore-proof
rm -rf "$RESTORE"; mkdir -p "$RESTORE/data"
tar xzf "$BK" -C "$RESTORE/data"

# 3. boot a throwaway on 7689 — the image MUST match the source version (5.26.21)
docker run -d --name epi-neo4j-restore-proof \
  -e NEO4J_AUTH=none -e NEO4J_server_memory_heap_max__size=2G \
  -p 7689:7687 -v "$RESTORE/data":/data neo4j:5.26.21

# 4. it is ready in ~3s; Neo4j replays its own transaction log on first start
docker exec epi-neo4j-restore-proof cypher-shell -a bolt://localhost:7687 --format plain "
MATCH (n:Bimba) WITH count(n) AS bimbaNodes
MATCH (m) WITH bimbaNodes, count(m) AS allNodes
MATCH ()-[r]->() WITH bimbaNodes, allNodes, count(r) AS allRels
MATCH (b:Bimba)-[br]-() WITH bimbaNodes, allNodes, allRels, count(DISTINCT br) AS bimbaRels
RETURN bimbaNodes, allNodes, allRels, bimbaRels;"

docker exec epi-neo4j-restore-proof cypher-shell -a bolt://localhost:7687 --format plain "
MATCH (n:Bimba) UNWIND keys(n) AS k WITH DISTINCT k
WHERE k STARTS WITH 'q_' OR k STARTS WITH 'qm_' RETURN count(k) AS distinctQKeys;"

# 5. tear down
docker rm -f epi-neo4j-restore-proof && rm -rf "$RESTORE"
```

**Promoting a restore to live** (only after the throwaway counts check out, and
only with the Architect's say-so):

```bash
.codex/scripts/neo4j-volume-backup.sh          # snapshot the CURRENT state first
docker stop epi-neo4j
docker run --rm -v epi-logoscexperiments_neo4j-data:/data -v ~/epi-backups/neo4j:/in \
  alpine:3.20 sh -c 'rm -rf /data/* && tar xzf /in/<SNAPSHOT>.tar.gz -C /data'
docker start epi-neo4j
```

## 5. Consistency: hot snapshot vs quiesced

The scheduled run takes a **hot** snapshot — `epi-neo4j` keeps serving. That is
safe because the archive carries `transactions/` as well as `databases/`, and
Neo4j runs its normal recovery pass when the restored copy first starts. The
restore proof below was taken hot and matched the source exactly.

For a guaranteed-quiesced copy (before a risky migration, say), stop first:

```bash
docker stop epi-neo4j
.codex/scripts/neo4j-volume-backup.sh
docker start epi-neo4j
```

## 6. The trap: `neo4j-admin database dump` will NOT work here

`neo4j-admin database dump` **requires a stopped database on Community edition**
and fails outright against a running one. `neo4j-admin database backup` (the
online, no-downtime one) is **Enterprise-only**. Query logging is Enterprise-only
too, which is why `query.log` is empty and always will be.

That is the whole reason this is a **file-level volume tar** and not a dump. If a
future reader "improves" this script into a `neo4j-admin database dump`, the
scheduled job will start failing silently against the running container. It is the
first thing to check when a backup stops appearing.

## 7. Editing the script (the TCC trap)

macOS **TCC denies launchd agents access to `~/Documents`**. Pointing the plist
straight at the repo copy dies with:

```
/bin/bash: /Users/admin/Documents/.../neo4j-volume-backup.sh: Operation not permitted
```

(verified live on 2026-07-29 — the first kickstart failed exactly this way). So:

- `.codex/scripts/neo4j-volume-backup.sh` is the **source of truth**;
- `~/epi-backups/neo4j-volume-backup.sh` is the **deployed copy launchd runs**.

After editing the repo copy, re-deploy:

```bash
cp ".codex/scripts/neo4j-volume-backup.sh" ~/epi-backups/neo4j-volume-backup.sh
chmod +x ~/epi-backups/neo4j-volume-backup.sh
```

`.codex/scripts/__tests__/neo4j-volume-backup.test.mjs` fails if the two drift.

## 8. Safety rails (and the exit codes that report them)

The disk was a **co-cause** of the incident, and a scheduled job that fills a
nearly-full disk causes the next one rather than preventing it. So:

| Rail | Behaviour | Exit |
|---|---|---|
| **Free-space floor — 5 GiB** | Refuses to write if free space is below the floor **or would fall below it after writing** (estimate = 2× the last snapshot). Logs `REFUSED: insufficient free space … NO snapshot taken`. | `2` |
| **Lock** | Atomic `mkdir ~/epi-backups/neo4j/.lock`. A second run skips its tick rather than interleaving. A lock whose pid is dead **and** older than 120 min is reclaimed with a logged warning; a fresh one is never stolen. | `3` |
| **Atomic write** | The archive is built in `.incoming/*.partial`, verified readable (`tar tzf`) and checked for `./databases/`, and only then renamed into place. A half-written file can never look like a backup. | `5` |
| **Retention scope** | `find -maxdepth 1 -name 'epi-neo4j-data-????????T??????Z.tar.gz' -mtime +7` — **only files this script created, matched by its own exact pattern**. Never a broad glob. The newest snapshot is age-exempt, so retention can never leave zero backups. | — |
| **Docker preflight** | Refuses if the docker binary or the named volume is missing (launchd's PATH is minimal; the plist sets an absolute `EPI_BACKUP_DOCKER`). | `4` |

Config overrides: `EPI_BACKUP_VOLUME`, `EPI_BACKUP_DIR`, `EPI_BACKUP_RETAIN_DAYS`,
`EPI_BACKUP_MIN_FREE_GIB`, `EPI_BACKUP_DOCKER`, `EPI_BACKUP_HELPER_IMAGE`,
`EPI_BACKUP_LOCK_STALE_MIN`.

**Raise the floor, not the risk:** if `~` routinely sits near 5 GiB free, fix the
disk. A refused backup is loud in `backup.log`; a full disk is not.
