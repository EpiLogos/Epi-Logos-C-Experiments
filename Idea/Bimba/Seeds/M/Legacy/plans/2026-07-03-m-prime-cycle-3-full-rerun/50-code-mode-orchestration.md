**The change, precisely.** Agents naturally run tools in JSON tool-mode — one call per model round-trip (the "staircase"), where every hop re-sends the whole history (`Body/S/S3/gateway-contract/src/harness.rs` `ToolCallObserved` re-inlines full `arguments`+`result` per step). This track makes **a single generated TypeScript program the default way agents compose tool calls**. JSON tool-mode remains the substrate; scripting becomes the default *usage*. Two tiers, one mechanism: **(base)** any pi agent collapses a multi-tool task into one script (token efficiency above all); **(VAK)** Anima composes orchestrations across the full six reflective C′ coordinates (CPF/CT/CP/CF/CFP/CS), with CP as the nesting operator, spawning child pi's for teams/chains. Each run is a bounded song; a repeatable one is a **score**; ELO/ML refine the scores.

4. **T50.04 — CP nesting: context-frame recursion (each position a leaf or a nested frame)**

   Brief: CP is the composability engine. A position within a context frame is EITHER a terminal dispatch (leaf) OR expands into a full nested context frame. Example: in `0/1/2`, position `0` can expand to `(00/00)`, position `1` to `(0/1)` or `1/0`; a parent like `(4.0/1-4.4/5)` can nest a full frame at each internal position. This is the `.`-nesting operator surfaced through CP, and it is what lets the language scale. In TS it is plain recursion — a frame is a function, each position resolves to a `dispatch(…)` leaf or a call into another frame — so no new abstraction is required. `CfPosition` (`Body/S/S0/portal-core/src/vak_address.rs`) already carries the frame identities (`Outer4Parent` = `(4.0/1-4.4/5)`, etc.).
   Build: a nesting evaluator in `Body/S/S4/ta-onta/S4-4p-anima/lib/vak-orchestration-surface.ts`; CP-address resolution so a nested frame spawns the correct child pi at each leaf; trace records the nesting depth.
