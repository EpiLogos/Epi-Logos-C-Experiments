# Track 51 — Specced-Surface Gap Closure: M′ sub-node surfaces with no tranche

**This track is hand-authored and self-contained — each tranche below carries its full brief inline** (there is no 2026-06-02 design-reconciliation source; do not look for one). Every tranche here closes a surface that is **already specced in canon and has zero coverage anywhere in the cycle-3 plan** — established by grepping all 50 existing track files for each surface's canonical name and its plausible variants. This is not new design; it is landing design that was written and then never scheduled.

**Why this track exists.** The M′ specs each carry a `User-Facing Surface` (or `Sixfold IDE Surface`) section that enumerates the sub-node surfaces of that subsystem. The cycle-3 frontend tracks (21–26) were cut from the design-reconciliation corpus and cover the surfaces that corpus happened to name — which is most of them, but not all. The remainder have sat specced-and-unplanned, invisible to the ledger because a task that was never written cannot show up as pending. A specced surface with no tranche is not "done", it is unaccounted for, and the no-orphan audit (Track 14) cannot see it either.

The five M′ surface tranches build in `Body/M/pratibimba-app` (panes/engine-carriers on the modulation graph, per the ratified widget-deprecation reorientation — deliver function carrier-native, never port an epi-theia widget). 1. **T51.1 — `s4'.context.assemble`: make context-pack assembly a real surface, and make the spine injection visible**

   Brief: `s4'.context.assemble` is named as an implementation hook in `Idea/Bimba/Seeds/S/S4/S4'/S4-4'-SPEC.md` ("API / Envelope / Implementation Hooks") and listed in that same file's `Open Gaps` — "`s4'.context.assemble`, richer `s4'.goal.*`, and persisted Psyche goal state remain open" — and again in `S4-4-SPEC.md` ("`nous_disclose` still uses a helper path for context; target `s4'.context.assemble` must route through explicit S1/S2/S3/S5 contracts"). Nothing in the cycle-3 plan mentions it. The concrete consequence landed during Track 50: `Body/S/S4/ta-onta/composite-entry.ts` assembles the six ta-onta carriers' spine contributions into a system-prompt injection on every session, and **nothing anywhere can see what it injects** — not the user, not the agent, not a test. It was in fact returning that injection from a `session_start` handler, which pi types with no result, so it was silently discarded entirely until 2026-07-25; a surface that had been dead for an unknown period, with no way to notice. That is precisely the class of silent behaviour the whole architecture exists to make visible.
   Build: implement `s4'.context.assemble` as a first-class gateway method (`Body/S/S3/gateway-contract/src/protocol.rs` `METHOD_NAMES` + handler in `Body/S/S3/gateway/src/dispatch.rs`), returning the assembled context pack with per-carrier provenance: which carrier contributed each block, its byte size, and its freshness. Route `composite-entry.ts`'s assembly through it so the injected pack and the reported pack are the same object, not two code paths that can diverge. Register the capability in `Body/S/S4/plugins/pleroma/capability-matrix.json` and keep `Body/S/S4/pi-agent/lib/capability-parity.ts` green.
   Then surface it: a context-pack view in the M5-4′ Agentic Control Room (`Body/M/pratibimba-app`) rendering the live pack per-carrier. The gateway method makes the injection visible to the AGENT; the ACR view makes it visible to the USER, and the surface exists to serve both. This tranche therefore spans S4′ and M5-4′ — which is ordinary, not a scope problem.
   Depends on Track 00 Tranche 3.
   Verify: real behavioral/live-wire proof per Track 00 — dispatch the new method over a spawned `epi gate start`, strict-Zod parse, and assert the returned pack is byte-identical to what a live session actually injects (not a re-assembly); capability-parity and no-tool-bypass pass; plus a UF e2e opening the ACR view and asserting it renders the same per-carrier pack the method returns. verify-all green, honesty-lint clean; verifier ≠ closer; evidence = fresh command output.
