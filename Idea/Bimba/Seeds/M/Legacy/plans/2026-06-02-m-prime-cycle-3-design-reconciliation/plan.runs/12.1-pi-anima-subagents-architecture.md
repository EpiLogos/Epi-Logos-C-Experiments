## 1. Canonical Architecture

The Agentic Control Room (M5-4') operational-capacity layer is governed by a three-tier architecture, not a flat actor parity model:

### Tier 1 — Harness
**Pi** is the single harness. It governs tool surface, entitlement contracts, and the dispatch lifecycle. Pi does not execute tasks — it provides the scaffold that makes execution governable. Every tool invocation, every subagent spawn, every capability exercise passes through Pi's entitlement gate.

### Tier 2 — Main Dispatcher
**Anima** is the single main dispatcher. It receives dispatch intents from the user (via the ACR surface), validates them against the capability matrix, and fans them out to the appropriate Aletheia subagent techne-guardians. Anima owns the dispatch genealogy — the trace from intent to completion. Anima does not execute; it routes.

### Tier 3 — Techne-Guardians (Aletheia Subagents)
Six subagent techne-guardians, each guarding a specific techne class in Pleroma-Techne. They are invoked by Anima, not directly by the user. Each is a skill/system/service specialist:

| Guardian | Techne Class | Domain |
|----------|-------------|--------|
| **Anansi** | System/Infrastructure | Filesystem, process, network, gateway substrate |
| **Janus** | Security/Boundary | Auth, privacy classification, IOD-17 parity enforcement |
| **Moirai** | Temporal/Causal | Scheduling, lifecycle, cron, session boundaries |
| **Mercurius** | Hermeneutic/Symbolic | Tarot, I Ching, astrological computation, Kairos |
| **Agora** | Social/Collaborative | Multi-agent coordination, review routing, consensus |
| **Zeithoven** | Creative/Generative | Code generation, artifact creation, visual output |

### Infrastructure — ta-onta Carriers
Six ta-onta carriers (`S4-0p-khora`, `S4-1p-hen`, `S4-2p-pleroma`, `S4-3p-chronos`, `S4-4p-anima`, `S4-5p-aletheia`) are system/service routing infrastructure. They are NOT agents — they carry messages, enforce contracts, manage state, and provide the substrate that agents operate on. They appear in the architecture as extension points, not as actors in `AgenticActor`.

**Proposed collapsed union:**
```ts
export type AgenticActor =
    | 'pi'        // Tier 1 — Harness
    | 'anima'     // Tier 2 — Main Dispatcher
    | 'aletheia'; // Tier 3 — Techne-Guardian (subagent, with techne discriminator)
```

The techne class (which guardian within Aletheia) is carried in the dispatch payload's `techneClass` field, not in the actor type itself. This keeps the type system aligned with the three-tier architecture while preserving the full 6-guardian resolution at runtime.

### Tangent — Deprecate
None of the 8 current actors are tangential. All map cleanly to the three-tier model. The deprecation is of the flat parity model itself, not of any specific actor name.

## 4. M5'-SPEC §M5-4' Rewrite

The following replaces the current M5'-SPEC §M5-4' section.

### §M5'.4 — Six Operational Capacities

M5-4' is the **operational-capacity layer** of the Epi-Logos system. It is governed by a three-tier architecture:

**Tier 1 — Pi (Harness).** Pi governs the tool surface, entitlement contracts, and dispatch lifecycle. Every capability exercise passes through Pi's entitlement gate. Pi is instantiated as `Body/S/S4/pi-agent/` with the canonical skill surface at `Body/S/S4/pi-agent/skills/`.

**Tier 2 — Anima (Main Dispatcher).** Anima receives user dispatch intents, validates them against the capability matrix (`Body/S/S4/plugins/pleroma/capability-matrix.json`), and routes them to the appropriate Aletheia techne-guardian. Anima owns the dispatch genealogy and maintains the audit trail. Anima is instantiated at `Body/S/S4/pi-agent/agents/anima.md`.

**Tier 3 — Aletheia Techne-Guardians.** Six subagent specialists, each guarding a specific techne class. Invoked by Anima, not directly by the user:

| Guardian | Techne Class | Capacity Paper |
|----------|-------------|----------------|
| Anansi | System/Infrastructure | `epii-on-anuttara-language-development` |
| Janus | Security/Boundary (IOD-17) | `epii-on-epii-self-referential-capacity` |
| Moirai | Temporal/Causal | `epii-on-mahamaya-process-reward-rl` |
| Mercurius | Hermeneutic/Symbolic | `epii-on-nara-qlora-dialogic-voice` |
| Agora | Social/Collaborative | `epii-on-parashakti-graph-relational-ml` |
| Zeithoven | Creative/Generative | `epii-on-paramasiva-ql-cpt-and-rag` |

**Infrastructure.** Six ta-onta carriers provide the routing and state substrate: Khora (S4-0', session identity and secrets), Hen (S4-1', ontology validation and template instantiation), Pleroma (S4-2', capability matrix and tool registry), Chronos (S4-3', temporal pathing and day/NOW lifecycle), Anima-extension (S4-4', dispatch routing infrastructure), Aletheia-extension (S4-5', subagent lifecycle and evidence collection). These are NOT agents — they are infrastructure that agents operate through.

**Governance.** All capability exercise is bound by:
- `Body/S/S4/plugins/pleroma/capability-matrix.json` — canonical agent-tool governance authority per IOD-17
- `Body/S/S5/epii-agent/agent-contract.json` — live `s5'.epii.*` / `s5'.review.*` / `s5'.improve.*` methods
- Pi entitlement contracts at `Body/S/S4/pi-agent/lib/entitlement.ts`

**The ACR `AgenticActor` type** reflects the canonical three-tier architecture as a collapsed union: `'pi' | 'anima' | 'aletheia'`. The specific techne-guardian within Aletheia is discriminated at runtime by the `techneClass` field in the dispatch payload, not by the actor type. This replaces the previous flat 8-member actor parity model.
