# Wave C — Design Language Layer Reconciliation Matrix

**Task id:** `wave-c-design-language`
**Domain:** Cross-cutting design language unifying the colour, typography, motion, light/dark, a11y, empty/loading/error state grammar, iconography, provenance primitives, and design tokens that stage-1 (Tracks 21–26) and the integration tracks (11, 15, 19) authored in fragments. This matrix is the cross-cutting DELTA — every visual choice scattered across stage-1 is named, traced to its coordinate-system derivation, and lifted into ONE design system grounded in Cl(4,2) signature, family-letter palette tiers, the DR streamline pair, and the highlight-category register.
**Scope discipline:** This matrix does NOT re-author the K² ananda heatmap colour-binary (15.8 owns), the slerp animation primitive (15.9 owns), the lemniscate transition (15.5 owns), the highlight categories (11.11 owns), the ambient state strip palette per-glyph (11.12 owns), the contemplation orbit colour register (19.11 owns), the per-Mn family widget pages (21–26 own), the readiness taxonomy (07-t0 contract owns), or the M4 privacy-class chrome triplet (25.18 owns). It lifts every named colour, every named font register, every named motion primitive, every named empty/loading/blocked rule, every named provenance affordance, every named iconographic choice scattered across those authorities into one canonical design-token bundle + design-primitive component shelf consumed by every M-extension.
**Anti-greenfield posture:** Every token lifted here exists in stage-1 prose. Theia's theming convention (`--theia-*` CSS variables; `ThemeService`; `ColorContribution`; `IconThemeService`) is the consumption path. The `m-extension-runtime` already exposes `ReadinessBanner` + CSS-var convention (`mext-banner-ok|degraded|blocked` with `--theia-successForeground|warningForeground|errorForeground` fallbacks) — the design system EXTENDS that pattern, never replaces it. No greenfield design framework. No competing token system.

## Standing invariants honored

- **Anti-greenfield (design-system band):** the colour-fragments, motion primitives, and state grammar already exist scattered across stage-1; this matrix lifts them into design-tokens emitted from one source-of-truth file, consumed via Theia's `--theia-*` CSS-var convention extended with `--epilogos-*` namespace. No new theme engine. No competing token format. The existing `mext-banner-*` palette pattern in `m-extension-runtime/style/index.css` IS the consumption convention; new tokens land in the same idiom.
- **Coordinate-derivation invariant.** Every chromatic, motion, or typographic choice MUST be traceable to a coordinate-system concept: family-letter → palette tier; Cl(4,2) signature → cool/warm halo binary; #0–#5 raw-archetype position → grade within tier; DR rings → flow streamlines; archetype 3/5/7/9 odd-syntax-layers → highlight category register; profile-tick → global render clock. Decoration without derivation is rejected.
- **Foundation Principle 2 (profile-tick as primary clock) is binding on motion.** Every motion primitive subscribes to the kernel-bridge profile-tick (15.6) — NO internal `requestAnimationFrame` / `setInterval` competes (15.9 single-primitive discipline). Tokens for `motion.tick.duration`, `motion.tick.easing` etc. are derived from `MathemeHarmonicProfile.tick12` advance cadence, not picked aesthetically.
- **Foundation Principle 3 (provenance always visible).** Every datum binding renders its readiness state inline through one of three primitives: `ProvenanceBorder` (border-tint), `PendingBadge` (inline badge), `BlockedOverlay` (full-overlay with reason). No separate "errors panel". State grammar derives from the kernel-bridge readiness taxonomy (9 ids) — tokens emitted per `severity` band with id-specific overrides.
- **Foundation Principle 5 (OmniPanel as `/` membrane).** All design primitives render identically across `daily-0-1` and `ide-deep` layouts — no layout-specific palettes. The OmniPanel itself consumes the same tokens as every M-extension widget.
- **Foundation Principle 8 (Theia conventions where they fit).** Status bar palette uses Theia `statusBar` colour tokens; activity bar uses Theia `activityBar` tokens; breadcrumbs use Theia `breadcrumb` tokens; tooltip uses Theia `editorHoverWidget` tokens. Epi-Logos overlays land via `--epilogos-*` namespace as overrides ONLY where Theia defaults conflict with the Cl(4,2) palette derivation.
- **Light/dark polarity preservation.** Cl(4,2) signature polarity is INVARIANT under theme inversion: cool-indigo at signature −1 stays cool (indigo→slate-blue in dark, indigo→steel in light); warm-amber at signature +1 stays warm (amber→ember in dark, amber→saffron in light). The polarity binary is meaning-bearing, not aesthetic-bearing; theme switch maps within polarity, never across.
- **Accessibility contracts are binding, not optional.** WCAG AA contrast (4.5:1 body, 3:1 large) enforced at token-emission level via design-token lint. Visible focus ring honours family palette. Reduced-motion preference disables tick choreography per 15.9 a11y note. Visual-only encodings (codon string, hexagram glyph, Cl(4,2) signature, family-tier hue) carry text equivalents in `aria-label` / screen-reader-only spans.
- **M4 protected-local privacy chrome remains the M4 surface concern.** The three privacy tints (earth `#8a7355` / slate `#6b7588` / gold `#d4a574`) from 25.18 ARE the canonical privacy-class chrome — the design system lifts them as `epilogos.colour.privacy.{protected_local,handle_only,opt_in}` tokens but their application (only on M4 surfaces) stays owned by 25.18. The status bar still does not host them per 15.10.

## Anomalies

### CONTRADICTIONS (decision-register candidates)

- **DR-WC-DL-1** — Family-tier palette derivation: should C-tier (Category, ontological foundation, contains Bimba/Pratibimba) read as deep-violet (deepest archetypal saturation) OR as foundation-neutral (precedes hue)? Two valid readings: (a) the ontological tier carries the deepest hue because it is the most-mediated category; (b) the ontological tier carries no hue because it IS the foundation. Cannot be decided by Wave-C alone — routes to user final-validation. **Proposed default: deep-violet** (C0/Bimba and C5/Pratibimba as the violet endpoints of the Cl(4,2) signature −1 polarity carries this reading; the family-tier hue stacks on top of the Cl(4,2) polarity colour-binary).
- **DR-WC-DL-2** — Psyche-facet palette derivation: should the seven facets derive from M-tier coordinates (sophia=M5, nous=M0, logos=M1, ...) OR from agent-function semantics (sophia=wisdom-gold, nous=clarity-indigo, ...)? Wave-A M5 (claim 16) names them as constitutional-roster — both readings have spec backing. **Proposed default: agent-function semantics** (matches 26.8 DR-WC-M5-3 default; the constitutional agents are roles not tiers).
- **DR-WC-DL-3** — Theme-set extension: should we add a new theme `epi-logos-bimba` (vault-aesthetic, parchment + ink-mono) as a peer to `nara-{dark,light,glass}`? Wave-A and stage-1 mention vault aesthetics for Canon Studio but no theme is explicitly requested. **Proposed default: NO new theme** — Canon Studio renders within `dark|light|glass` honouring its content typography (markdown editor); vault aesthetic emerges from the `epilogos.typography.matheme.*` + `epilogos.typography.mono.coordinate` tokens, not a new theme.
- **DR-WC-DL-4** — Reduced-motion baseline: should reduced-motion disable ALL motion (including transitions on toggle) OR only continuous tick choreography? **Proposed default: only continuous tick choreography** — discrete state transitions (lemniscate toggle, layout switch) remain animated but at minimum duration (100ms snap); continuous slerp and DR streamline advance pause/freeze on reduced-motion.
- **DR-WC-DL-5** — Visual-regression-baseline scope: should every Wave-C widget have a regression baseline (~100 fixtures) OR only the cross-cutting primitives (~20 fixtures)? **Proposed default: cross-cutting primitives + per-extension flagship fixture** (~30 total). Avoid baseline-bloat; per-extension widgets test their own visual contracts in extension test suites.
