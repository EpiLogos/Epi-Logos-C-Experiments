# Unified Coordinate Header Convention

**Convention:** `convention:coordinate-header:v1`<br>
**Status:** Track 43 doc-ahead landing; registers through [[40-bimba-canon-update-ledger]] and Track 16 CCT closure.<br>
**Scope:** Named code units and seam contracts across [[S-SYSTEM-INDEX]], [[S1'-SPEC]], and [[M'-SYSTEM-SPEC]] surfaces.<br>
**Owner after landing:** [[S1-SPEC]] / Hen validation, with agent-authoring support from the future `coordinate-header` skill.

## Purpose

The repo already uses one interface intention: coordinate, responsibility, narrow public surface, and explicit non-ownership. The audit found that intention split across Rust `Cargo.toml` descriptions, ad hoc Rust `//!` module docs, C header prose, S4/S5 `CONTRACT.md`, and the M-stack JSON contract surface. This convention makes the intention one logical schema with language-specific renderings so an agent can traverse S0 -> S4 -> M' and know exactly where to look.

## Scope

A Coordinate Header is mandatory on every named code unit:

- C public headers: `include/*.h`.
- Rust entry modules: `src/lib.rs`, `src/main.rs`, and public `mod.rs` barrels when they define a boundary.
- TypeScript/JavaScript extension barrels, top-level service modules, public component roots, and contract-facing modules.
- Agent skills and plugin entry surfaces.
- `CONTRACT.md` files for crates/extensions with a real seam.

Leaf implementation bodies (`.c`, ordinary private `.rs`, ordinary private `.ts`) do not need a full header unless they are themselves a public boundary. They still conform to the nearest declaring header or contract.

## Logical Schema

All Coordinate Headers carry these seven field labels in this order. The labels are mandatory even when a field's value is explicitly `None`.

| Field | Requirement | Contract |
|---|---|---|
| `Coordinate` | Mandatory | Canonical coordinate or coordinate shard this artifact declares. Do not infer from path alone. |
| `Residency` | Mandatory | Physical repo path. If physical residency differs from conceptual ownership, include `conceptual: ...` in the value per the Track 17 substrate-residency note. |
| `Position (#n)` | Mandatory | Position number and role phrase. Use the local spec vocabulary; do not redefine coordinate meaning here. |
| `Actualises` | Mandatory | Owning spec, architecture doc, CCT, DR, plan tranche, or contract this artifact makes executable. Prefer `[[wikilinks]]` in markdown and stable path references in code comments. |
| `Public surface` | Mandatory | Exported functions, types, commands, tools, fields, or files that downstream consumers may depend on. Keep this narrow. |
| `Does NOT own` | Mandatory | Explicit negative space. Name adjacent responsibilities this artifact must not absorb. |
| `Contract` | Mandatory label | Link to `CONTRACT.md` when a real seam exists. Otherwise write `None — <reason>`. |

The schema is logical, not cosmetic: field order, labels, and negative-space wording are the validation target for Hen. Local prose can be richer, but these seven fields must remain machine-discoverable.

## Renderings

### Rust

Rust uses a crate/module-level `//!` block at the first lines of `src/lib.rs`, `src/main.rs`, or public `mod.rs`.

```rust
//! <crate-or-module> — <one-line purpose>
//!
//! # Coordinate Header
//!
//! | Field | Value |
//! |---|---|
//! | Coordinate | <coordinate> |
//! | Residency | <physical path; conceptual: <coordinate owner> when different> |
//! | Position (#n) | #<n> — <role> |
//! | Actualises | <spec / architecture / tranche / contract reference> |
//! | Public surface | `<ExportA>`, `<ExportB>`, `<command>` — <bounded summary> |
//! | Does NOT own | <negative-space commitments> |
//! | Contract | <path to CONTRACT.md> or None — <reason> |
```

Rules:

- The `//!` block precedes attributes, imports, and module declarations.
- Public surface entries name stable symbols or modules, not implementation internals.
- `Cargo.toml description` remains useful package metadata, but it is not the Coordinate Header.

### TypeScript / JavaScript

TypeScript and JavaScript use a top-JSDoc block before imports.

```ts
/**
 * <module> — <one-line purpose>
 *
 * Coordinate: <coordinate>
 * Residency: <physical path; conceptual: <coordinate owner> when different>
 * Position (#n): #<n> — <role>
 * Actualises: <spec / architecture / tranche / contract reference>
 * Public surface:
 *   - <ExportA> — <bounded contract>
 *   - <ExportB> — <bounded contract>
 * Does NOT own:
 *   - <negative-space commitment>
 *   - <negative-space commitment>
 * Contract: <path to CONTRACT.md> or None — <reason>
 */
```

Rules:

- The block is the first statement in the file.
- M-stack barrels preserve the pointer to `Body/M/epi-theia/extensions/contracts/07-t0-extension-contract-preflight.json` when they sit on a forbidden-import boundary.
- Generated barrels may be regenerated, but the generator must emit the same seven fields.

### C Headers

C public headers use the existing top comment block before the include guard, normalized to the same seven labels.

```c
/**
 * <header.h> — <one-line purpose>
 *
 * Coordinate: <coordinate>
 * Residency: <physical path; conceptual: <coordinate owner> when different>
 * Position (#n): #<n> — <role>
 * Actualises: <spec / architecture / tranche / contract reference>
 * Public surface:
 *   - <type_or_function> — <bounded contract>
 * Does NOT own:
 *   - <negative-space commitment>
 * Contract: <path to CONTRACT.md> or None — <reason>
 */
```

Rules:

- Headers declare; sibling `.c` files define. Algorithms, LUT bodies, heap ownership, and non-trivial `static inline` implementations belong in `.c` unless 43.4 explicitly permits the inline.
- `Public surface` names declarations that consumers may include against.
- `Does NOT own` must state at least implementation bodies, allocation, or adjacent coordinate authority when relevant.

### CONTRACT.md

For crates/extensions with a real seam, `CONTRACT.md` is the full contract body and carries the same header fields near the top.

```markdown
# <Name> Contract

**Coordinate:** <coordinate>
**Residency:** <physical path>
**Position (#n):** #<n> — <role>
**Actualises:** <owning spec / architecture / tranche>
**Public surface:** <tools, commands, exports, hooks>
**Does NOT own:** <negative-space commitments>
**Contract:** self

## Responsibility
...
## Integration Surface
...
## Dependencies
...
## Key Invariants
...
```

The code header is the compact mandatory subset; `CONTRACT.md` is the expanded seam. When both exist, they must agree on coordinate, residency, public surface, and non-ownership.

## Residency Law

`Residency` is always the physical path of the file being read. Conceptual ownership is added only when it differs:

```text
Residency: Body/S/epi-kernel-contract/src/lib.rs; conceptual: parent-role kernel contract across S0..S5
```

This prevents convenience residency from silently becoming coordinate ownership. Track 17 remains the substrate-residency source; this convention only makes the mismatch visible in every boundary file.

## Hen Validation Contract

Hen validates this convention as code-side navigability, sibling to vault-side frontmatter validation.

Validation checks:

1. Presence on every scoped boundary file.
2. All seven field labels present in order.
3. `Coordinate` parses under the canonical coordinate grammar.
4. `Residency` equals the real repo-relative path.
5. Conceptual/physical mismatch is explicit when present.
6. `Contract` path exists when not `None`.
7. `CONTRACT.md` and code header agree where both exist.
8. `Public surface` does not list private implementation symbols as consumer contract.
9. `Does NOT own` is non-empty and names at least one adjacent boundary.

Initial enforcement should warn during the 43.3 migration pass, then fail the 43.5 lint once coverage lands.
