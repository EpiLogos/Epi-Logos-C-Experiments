# Unified Coordinate Header Convention

**Version:** 1.0.0
**Status:** Canonical (Track 40 intake)
**Audience:** All S0–M' contributors and automated tooling (Hen S1', bimba-canon-update-ledger)
**CCT:** `convention:coordinate-header:v1`

---

## 1. Problem Statement

The Epi-Logos coordinate system places every artifact at a precise position in (S, L, P, C, M) space. The API-header intent is uniform everywhere — *coordinate + responsibility + narrow surface + explicit non-ownership* — but it is currently expressed in **three unaligned media**:

| Medium | Coverage | Gap |
|--------|----------|-----|
| C header `/* */` block | ~95% of C headers | Inconsistent field ordering; some omit residency |
| Rust `//!` module-doc | ~18% of crates | Most crates have no coordinate header at all |
| TypeScript top JSDoc | ~5% of TS modules | No convention exists |
| CONTRACT.md | ta-onta (100%), S5 epi-kbase (100%) | No other crates use it |

An agent (human or automated) traversing S0 → S4 → M' must learn **three places to look** and cannot rely on uniform presence. Hen (S1' ontology validator) cannot compile/validate coordinate claims because there is no single schema to validate against.

## 2. The Unified Schema

Every artifact that is a **named unit of code** (header, module, crate entry-point, extension root, agent skill, contract) SHALL carry a Coordinate Header. The header is **one logical schema, dual-rendered**:

### 2.1 Schema Fields

| Field | Required | Semantics |
|-------|----------|-----------|
| `Coordinate` | **Yes** | The artifact's canonical coordinate in the system, e.g. `S0-3-1` (Stack 0, Layer 3, Position 1) or `M'-4-0` |
| `Residency` | **Yes** | Physical filesystem path. Flagged when the physical path differs from the conceptual coordinate (Track 17 substrate-residency note). E.g. `Body/S/S0/epi-lib/include/ontology.h` |
| `Position (#n)` | **Yes** | The artifact's functional role in the coordinate family, e.g. `#0 — Ontological Foundation`, `#3 — Pattern / Temporal Structure` |
| `Actualises` | **Yes** | What spec/design/contract this artifact makes real. Link to Seeds doc, CONTRACT.md, or spec section. |
| `Public surface` | **Yes** | Exported symbols, functions, types, or tool registrations that external consumers may depend on. |
| `Does NOT own` | **Yes** | Explicit negative space — what this artifact deliberately does NOT own, to prevent scope creep and ownership ambiguity. |
| `Contract` | *No* | Link to CONTRACT.md for crates with a real seam (ta-onta pattern). Omit for leaf utility headers. |

### 2.2 Rendering by Language

#### C Headers (`/* */` block, before `#ifndef` guard)

```c
/**
 * <filename> — <one-line purpose>
 *
 * Coordinate:   S<stack>-<layer>-<pos>   |   <family-indicator>
 * Residency:    Body/S/S<stack>/<path>
 * Position:     #<n> — <role name>
 * Actualises:   <Seeds doc or spec reference>
 * Public surface:
 *   <function/type> — <purpose>
 *   ...
 * Does NOT own:
 *   <exclusion>
 *   ...
 * Contract:     Body/S/S4/ta-onta/<name>/CONTRACT.md   (if seam exists)
 */
```

**Exemplar — `ontology.h`:**
```c
/**
 * ontology.h — The Master Blueprint
 *
 * Coordinate:   S0-0-0   |   C (Category)
 * Residency:    Body/S/S0/epi-lib/include/ontology.h
 * Position:     #0 — Ontological Foundation
 * Actualises:   Seeds/M/Legacy/plans/.../M-PRIME-ARCHITECTURE §2.1
 * Public surface:
 *   Coordinate_Family enum          — distinguishes raw psychoids from family manifestations
 *   Holographic_Coordinate struct   — 128-byte universal coordinate container
 *   Tagged Pointer macros           — ontology baked into addresses
 *   BEDROCK() accessor              — coordinate-to-archetype binding
 * Does NOT own:
 *   Any psychoid data (.rodata belongs in archetypes.c)
 *   Any function bodies (implementations belong in src/)
 *   Any memory allocation
 */
```

#### Rust (`//!` module-doc, first lines of `lib.rs` / `main.rs` / `mod.rs`)

```rust
//! <crate-name> — <one-line purpose>
//!
//! # Coordinate
//!
//! | Field | Value |
//! |-------|-------|
//! | Coordinate | S<stack>-<layer>-<pos> |
//! | Residency  | Body/S/S<stack>/<crate-path> |
//! | Position   | #<n> — <role name> |
//! | Actualises | <Seeds doc or spec reference> |
//!
//! # Public surface
//!
//! * `<function>` — <purpose>
//!
//! # Does NOT own
//!
//! * `<exclusion>`
//!
//! # Contract
//!
//! See [`CONTRACT.md`](Body/S/S4/ta-onta/<name>/CONTRACT.md) for the full seam contract.
```

**Note:** Rust `//!` blocks use Markdown headings inside the module-doc. This renders correctly in `cargo doc` and is grep-friendly.

#### TypeScript / JavaScript (top JSDoc, before imports)

```ts
/**
 * <module-name> — <one-line purpose>
 *
 * @coordinate   S<stack>-<layer>-<pos>  |  <family-indicator>
 * @residency    Body/M/epi-theia/extensions/<path>
 * @position     #<n> — <role name>
 * @actualises   <Seeds doc or spec reference>
 *
 * Public surface:
 *   <Component/function> — <purpose>
 *
 * Does NOT own:
 *   <exclusion>
 *
 * @contract     Body/S/S4/ta-onta/<name>/CONTRACT.md
 */
```

#### CONTRACT.md (for crates with a real seam)

Follow the existing ta-onta pattern:

```markdown
# <Name> Contract — <one-line purpose>

**Extension class:** <S4-N' or M-N'> within <parent>
**S-Layer fold:** <layer description>
**Position:** #<n> (<role name> — <semantic expansion>)

---

## Responsibility
...
## PI Hook Seams
...
## Registered Tools
...
## Dependencies
...
## Key Invariants
...
```

CONTRACT.md is the **full seam specification**. The in-code Coordinate Header is the **compact mandatory subset**. They must agree; Hen validates this.

## 3. Validation Rules (Hen S1')

Hen SHALL validate:

1. **Presence:** Every file matching `include/*.h`, `src/lib.rs`, `src/main.rs`, `extensions/*/src/browser/*.tsx`, `extensions/*/src/common/*.ts`, `ta-onta/*/CONTRACT.md`, `skills/*/SKILL.md` MUST carry a Coordinate Header.
2. **Schema completeness:** All seven fields present (Contract is optional).
3. **Coordinate validity:** The `Coordinate` field must parse to a valid coordinate in the canonical coordinate system.
4. **Residency match:** The `Residency` field must match the file's actual path. Flag if conceptual coordinate ≠ physical path (Track 17 note).
5. **Contract link validity:** If `Contract` is present, the linked file must exist.
6. **CONTRACT.md agreement:** If both a Coordinate Header and a CONTRACT.md exist for the same coordinate, their Coordinate, Position, Public surface, and Does NOT own fields must agree.

## 5. Migration Path

### Phase 1 — Canonicalise exemplars (now)
The existing exemplars are ~95% conformant. Add the explicit `Coordinate:`, `Residency:`, `Actualises:`, and `Does NOT own:` field labels to the existing comment blocks.

### Phase 2 — Hen validation (with Track 40)
Register this convention in the bimba-canon-update-ledger (Track 40). Hen begins validating presence and schema completeness on `epi check`. Non-blocking warnings initially.

### Phase 3 — Full coverage (ongoing)
All new files carry a Coordinate Header at creation time. Existing files are backfilled crate-by-crate. Target: 100% coverage of named code units.
