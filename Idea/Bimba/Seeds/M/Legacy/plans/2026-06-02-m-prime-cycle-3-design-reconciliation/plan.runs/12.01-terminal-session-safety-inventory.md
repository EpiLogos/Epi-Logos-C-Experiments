# 12.T12.01 terminal session-safety inventory and binding contract

Status: binding preflight inventory for later Track 12 implementation rows.

Scope: this tranche records current terminal/session safety gaps and defines the canonical `TerminalBinding` / `TerminalLease` contract. It does not change implementation files.

## Source evidence

1. `epi agent --persist` routes into the tmux envelope path, not the normal PI execution path. In `Body/S/S0/epi-cli/src/agent/spawn.rs`, `spawn(...)` builds a `PiLaunchPlan` and returns `crate::agent::tmux::run_plan(&plan, json)` when `persist` is true; otherwise it calls `execute_plan(&plan, json).await` (`spawn.rs:40-52`).

2. `agent/tmux.rs::run_plan` creates or reuses a tmux session envelope and reports `tmux new-session`; it does not inject the planned PI launch command into the pane. `run_plan` derives a tmux session name and delegates to `ensure_session` (`tmux.rs:73-75`). `ensure_session` runs `tmux new-session -d -s <session> -c <repo_root>`, sets environment variables such as `EPI_AGENT_ID`, `EPI_AGENT_DIR`, and `EPI_AGENT_GATEWAY_URL`, then returns a report whose command is `"tmux new-session"` (`tmux.rs:85-122`). There is no `send-keys`, `split-window`, or launch-command injection in that path.

3. `SessionRecord` carries cmux placement and CLI session IDs, but no first-class tmux terminal lease. In `Body/S/S3/gateway-contract/src/lib.rs`, `SessionRecord` includes `cmux_workspace`, `cmux_surface`, `cmux_pane_id`, and `cli_session_ids` (`lib.rs:3311-3333`). `SessionPatch` likewise patches `cmux_workspace`, `cmux_surface`, `cmux_pane_id`, and `cli_session_ids` (`lib.rs:3370-3375`). There is no `TerminalBinding` or `TerminalLease` symbol in the S0/S3/S4 Rust/TypeScript surfaces checked for this inventory.

4. Runtime subagent records and reports propagate only cmux placement, not terminal lease authority. `RuntimeSubagentRequest` includes `cmux_workspace`, `cmux_surface`, and `cmux_pane_id` (`Body/S/S0/epi-cli/src/agent/subagents.rs:43-53`), and `RuntimeSubagentReport` returns the same cmux fields (`subagents.rs:56-69`). The runtime listing emits `cmuxWorkspace`, `cmuxSurface`, and `cmuxPaneId` with `"status": "tracked"` (`subagents.rs:384-414`).

5. Gateway RPC patching can carry cmux metadata and CLI session IDs, but not terminal bindings. The `sessions.patch` handler constructs `SessionPatch` from fields including `cmuxWorkspace`, `cmuxSurface`, `cmuxPaneId`, and `cliSessionIds` (`Body/S/S0/epi-cli/src/gate/server.rs:424-595`). The local S0 CLI `epi gate sessions patch` is narrower: the command documents `vak_address` support and exposes only `--session-id` plus `--vak-address-json` (`Body/S/S0/epi-cli/src/gate/mod.rs:134-153`, `gate/mod.rs:333-352`).

6. Gateway/Redis/SpaceTimeDB already publish session surfaces, but terminal state is not part of that projection. `publish_session_surface` hydrates Redis temporal context, publishes the session record, and optionally registers the session agent (`Body/S/S0/epi-cli/src/gate/spacetimedb_bridge.rs:71-88`). The `session_surface` payload includes temporal, Redis, kernel, Pratibimba, graphiti, agent, workspace, and cmux fields, ending with `cmuxWorkspace`, `cmuxSurface`, and `cmuxPaneId` (`spacetimedb_bridge.rs:210-238`); it has no terminal binding field.

7. `PortalTemporalSurface` mirrors gateway/session temporal state, not terminal state. Its fields include session identity, runtime CWD, Redis hydration, SpaceTimeDB projection tables, Pratibimba anchor, and kernel tick/energy fields (`Body/S/S0/epi-cli/src/portal/runtime_state.rs:14-49`). `from_clock_and_session` initializes those fields from local session state and clock state (`runtime_state.rs:51-123`), while `from_gateway_context` reads `/session/*`, `/redis/*`, `/spacetimedb/*`, `/pratibimba/*`, and `/kernel/*` pointers (`runtime_state.rs:125-276`). No terminal provider, tmux pane, lease, capture, or redaction field is present.

8. Pleroma exposes bounded cmux visibility helpers, but its direct cmux management tools still shell out to cmux and use patch calls that are not aligned with the current S0 CLI surface. `techne_cmux_list_workspaces` and `techne_cmux_identify` call `epi techne cmux ... --projected` and describe visibility-only behavior (`Body/S/S4/ta-onta/S4-2p-pleroma/extension.ts:127-147`). Direct management tools call `cmux surface-create`, `cmux pane-assign`, `cmux focus`, and `cmux surface-destroy` (`extension.ts:156-203`, `extension.ts:228-257`). `techne_cmux_pane_assign` attempts `epi gate teams patch ... --cmux-pane-id ... --cf-identity ...` (`extension.ts:196-200`), but the current S0 `epi gate` command list has `sessions` and no `teams` subcommand; `epi gate methods` exposes `sessions.patch` but no `teams.patch`.

9. Pleroma still recognizes that interactive primitives require a terminal pane, but this is expressed as a refusal message rather than as a governed lease. For interactive execution modes, the extension returns an error saying the primitive "cannot be invoked as a bounded tool" and to use a tmux/cmux pane directly (`Body/S/S4/ta-onta/S4-2p-pleroma/extension.ts:314-323`). That direct pane instruction is not session-key-bound authority.

## Binding gaps

1. Persistent PI launch gap: `epi agent --persist` establishes a tmux session envelope with environment, but the launch plan is not sent into the pane. Later implementation must either inject the canonical launch command or explicitly model the envelope as reserved but not running.

2. Authority gap: current records expose `cmuxPaneId` as placement metadata. They do not express who owns a terminal, why it is held, when it expires, or which gateway session key grants authority over it.

3. Projection gap: Gateway, Redis hydration, SpaceTimeDB session surfaces, and portal runtime state already carry session context, but terminal state is absent from those surfaces. Later rows must project terminal state through the same gateway session key, not as an independent pane registry.

4. Capture gap: direct tmux/cmux output capture has no first-class capture policy. The default must remain metadata-only until a session-scoped bounded capture request exists and a redaction policy has been applied.

5. S4 tool gap: Pleroma visibility helpers are bounded, but management helpers can still shell out directly and some attempted patch paths are stale against the current S0 CLI. Later rows must route placement/binding changes through supported gateway/session authority.

## Canonical contract

`TerminalBinding` is the durable session-facing record. `TerminalLease` is the authority subshape that makes a binding usable for a bounded purpose. Implementations may store them as one struct or nested structs, but the field names below are canonical for gateway JSON, SpaceTimeDB projection, Redis context, and S4 tool contracts.

```ts
type TerminalBinding = {
  terminalProvider: "tmux" | "cmux";
  tmuxSession: string;
  tmuxWindow: string | null;
  tmuxPaneId: string | null;
  terminalStatus: "reserved" | "running" | "attached" | "detached" | "exited" | "stale" | "revoked";
  leaseOwner: string;
  leasePurpose: string;
  leaseExpiresAtMs: number;
  lastObservedAtMs: number;
  capturePolicy: "metadata-only" | "bounded-output";
  redactionPolicy: string;
  attachedSessionKey: string;
  attachedAgentId: string | null;
  lastRunId: string | null;
};

type TerminalLease = Pick<
  TerminalBinding,
  | "terminalProvider"
  | "tmuxSession"
  | "tmuxWindow"
  | "tmuxPaneId"
  | "terminalStatus"
  | "leaseOwner"
  | "leasePurpose"
  | "leaseExpiresAtMs"
  | "lastObservedAtMs"
  | "capturePolicy"
  | "redactionPolicy"
  | "attachedSessionKey"
  | "attachedAgentId"
  | "lastRunId"
>;
```

Binding rules:

1. `attachedSessionKey` is mandatory. Terminal authority is always attached to a gateway session key; terminal authority is never granted by naked `tmuxPaneId`, `cmuxPaneId`, tmux session name, or window name.

2. `terminalProvider` names the provider that owns the observed terminal surface. `tmuxSession`, `tmuxWindow`, and `tmuxPaneId` are provider coordinates, not authority tokens.

3. `terminalStatus` is the observed lifecycle state. A stale or expired lease must not authorize attach, capture, send-key, or kill operations.

4. `leaseOwner` and `leasePurpose` are required for every active lease. Later rows must reject anonymous or purpose-free terminal authority.

5. `leaseExpiresAtMs` is required and must be checked before terminal operations. Renewal must be explicit and session-scoped.

6. `lastObservedAtMs` records the last provider observation. It is not a lease extension.

7. `capturePolicy` defaults to `metadata-only`. `bounded-output` requires an explicit request tied to `attachedSessionKey`, a bounded byte/line/window limit, and `redactionPolicy`.

8. `redactionPolicy` is required even for `metadata-only`; the default policy may be named, but not omitted. Any bounded output capture must apply redaction before projection into gateway, Redis, SpaceTimeDB, logs, or S4 tool responses.

9. `attachedAgentId` and `lastRunId` bind the terminal lease to the agent/run using it when known. They do not replace `attachedSessionKey`.

10. Session surfaces may expose binding metadata, but pane output is never projected by default. Output capture is an exceptional, explicit, redacted, bounded operation.

## Implementation obligations for later rows

1. Add a first-class terminal binding to the gateway session model before giving S4 tools terminal authority.

2. Teach persistent launch either to inject the planned PI command into the tmux pane or to publish a `reserved` binding that clearly states no agent process is running.

3. Replace direct pane-id authority in S4 tools with session-key-bound lease checks.

4. Project terminal binding metadata through gateway session surfaces, Redis temporal context, SpaceTimeDB session surfaces, and portal runtime state.

5. Keep capture metadata-only by default; implement bounded output capture only behind explicit session-scoped request plus redaction.

6. Remove or update stale Pleroma `epi gate teams patch` assumptions before relying on direct cmux management tools.
