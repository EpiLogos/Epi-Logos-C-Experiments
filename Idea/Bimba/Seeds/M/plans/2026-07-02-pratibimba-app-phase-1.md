## Binding protocol (from the ratified §7 corrections — no exceptions)

1. **Verifier ≠ closer.** The agent that implements a task does not mark it done; a distinct verification pass runs the task's check command and records real output here, under the task.
2. **Behavioral tasks need behavioral proof** — a test that mounts/boots/interacts (jsdom at minimum, live app for gates). Manifest/string assertions close nothing.
3. **Sprint gate = drivable loop**, demonstrated by launching the real app (recording or observed run) plus the scripted checks. No ledger prose satisfies a gate.
4. **Any cited decision must exist and be VALIDATED** in [[M'-SURFACE-REENVISIONING-2026-07-01]] §8 or the cycle-3 register — quote it, don't name-drop it.
5. Banned as evidence: "design only", "deferred", "direct close", file-existence, test-count-without-test-content.

Task status markers: `[ ]` pending · `[~]` implemented-unverified · `[x]` verified (verifier initials/date + output snippet).

## Build law (Architect correction #2, 2026-07-02)

**Build from the specs, not from the failed carrier.** Tasks are defined by the owning spec's requirements and readiness criteria — never as "port X from epi-theia." The cycle-3 audit showed the Theia build was substantially hollow; anchoring tasks to its artifacts re-imports the failure (the wire-protocol and tick-conflation bugs found on day one were both inherited exactly that way). Code from ANY prior carrier may be *cribbed* only after reading it and verifying it against spec and a live surface; cribbed code counts as new code — it lands with behavioral tests and a provenance line, or not at all. Recon-before-build: any task naming a gateway method verifies it exists in `epi-cli/src/gate/server/dispatch.rs` first; if the method is missing, the gateway work surfaces to the Architect as its own task — never a stub render.

**Gateway singleton law:** there is ONE gateway process system-wide (port 18794, `epi up`-managed process record at `.epi/gate/up/gateway-process.json`). The app adopts a live gateway (`external`), spawns only when absent, and NEVER kills or duplicates it implicitly; restart is an explicit user-invoked, record-respecting operation.
