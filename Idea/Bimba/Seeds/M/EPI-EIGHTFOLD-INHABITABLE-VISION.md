# Epi Eightfold Inhabitable Vision

## 0. What is being corrected

The eightfold product field remains canonical.

The correction is not a reduction from eight to six or from six to four. It is a correction of **application embodiment**.

The canonical product arithmetic is:

```text
4 + 2 + 2

FOUR foreground recursive deep instruments
    M1′ Paramaśiva
    M2′ Paraśakti
    M3′ Mahāmāyā
    M4′ Nara

PLUS TWO implicit recursive deep dimensions
    M0′ Anuttara — ground / source / relation / world intelligibility
    M5′ Epii — articulation / agency / pedagogy / recognition / return

PLUS TWO parent 3:3 composed worlds
    epi.cosmic.123   = 1 / 2 / 3
    epi.personal.450 = 4 / 5 / 0
```

All six M′ domains remain complete recursive 4+2 depths. All six remain addressable and can be brought into explicit foreground inspection. The asymmetry is experiential: **M0 and M5 are normally implicit dimensions of the inhabited application, while M1–M4 are the principal objects/instruments a person enters and works through.**

The previous eightfold documents were correct that six deep products exist and that all six can open at depth. What they did not say sharply enough is that `M0′` and `M5′` should not be designed as if they were merely two more sibling tools beside M1′–M4′. Their ordinary role is constitutive of the whole workbench.

This matters because the system is intended to support eudaimonic development at every available level of identity: lived activity, symbolic interpretation, world relation, formal structure, source-ground, self-articulation and return. The application should make that depth usable without making the person administrate six disconnected specialist programs.

## 1. The fundamental experiential relation

The desktop is one inhabitable field in which differentiated instruments disclose one underlying semantic world.

```text
                 M5 / Epii
     articulation · agency · editing · return
                       ▲
                       │
      ┌──────────────────────────────────┐
      │                                  │
      │    M1      M2      M3      M4    │
      │                                  │
      │  foreground deep instruments     │
      │  opened in tabs / groups /       │
      │  splits / native workspaces       │
      │                                  │
      └──────────────────────────────────┘
                       │
                       ▼
                 M0 / Anuttara
      ground · knowledge · relation · source
```

This diagram is an application relation, not a replacement for the sixfold coordinate system.

M0 and M5 can themselves become foreground objects when the user explicitly wants to inspect the ground or inspect the system's self-articulation. Deep M0 and deep M5 therefore remain genuine products. But their deepest application value is that they are also **already present everywhere**:

- when a thing is addressable, sourced, related, navigable, provenance-bearing or situated in Bimba, M0 is active;
- when a thing can be explained, edited, discussed with canonical Agency, compared to canon, reflected upon, proposed, recognised or returned, M5 is active.

The product therefore becomes simpler without becoming shallower.

## 2. Why the asymmetry is native to the 4+2 grammar

The recursive sixfold was never a flat collection of equivalent modules.

Within each deep M′ domain the `.0/.5` framing pair grounds and returns the four differentiated inner dynamics. At whole-application scale the same relation appears again:

```text
M0
    implicit ground of addressability, source and relation

M1 / M2 / M3 / M4
    differentiated objects of formal, vibrational, symbolic and lived experience

M5
    implicit articulation, recognition and return
```

This does not make M0 and M5 mere infrastructure. It makes their infrastructure-like application role intelligible as an expression of their semantic position.

The four foreground instruments are not independent worlds either. Their difference is useful because each reveals a different depth of the same current event/subject through the shared Epi/QL source, coordinate, kernel and provenance field.

## 3. The two parent 3:3 worlds remain whole products

The two parent products are the second `+2` in the eightfold.

### 3.1 `epi.cosmic.123`

Cosmic remains one current situated world composed from:

```text
M1 — current act / QL movement / topology
M2 — current world-condition / harmonic / celestial relation
M3 — current inscription / clock / symbolic state
```

It is not three cards and not three deep instruments kept permanently open.

Its purpose is to make one current event cosmically intelligible. Any displayed relation should be able to open the corresponding deeper M1′, M2′ or M3′ workspace without minting a new event.

### 3.2 `epi.personal.450`

Personal is now even clearer:

```text
M0 — implicit ground / source / relation
M4 — foreground lived subject / activity / body / trajectory
M5 — implicit dialogue / explanation / pedagogy / recognition / return
```

The ordinary experience is therefore naturally activity-first:

```text

DAY / NOW
flow / activity organisation
oracle / reading
dialogue with canonical Epii Agency
Explain / History / provenance
Bimba/source/canon reveal
proposal / recognised return
```

This is why Personal never wanted to look like three equal permanent subsystem panes. The current Nara activity is foreground; Anuttara and Epii frame, disclose and return it.

The full M4′ psychoid organism remains a separate deep foreground instrument when explicitly entered.

## 4. The desktop experience: workspaces, not mini-applications

The intended desktop experience is a professional persistent workbench.

A person can keep several focused workspaces open at once:

```text
Tab/group A    deep M1 played/formal workspace
Tab/group B    deep M3 clock/transcription workspace
Tab/group C    Personal journal / Nara work
Tab/group D    explicit M0 cartography / source traversal
```

These may be arranged in tabs, split groups or alternate native Surfaces according to the ordinary O:I desktop grammar.

The phrase **session workspace** is an experiential description, not a new semantic type. A tab/group may preserve selected refs, local instrument state and presentation state inside a current SessionSpace, but:

```text
tab != semantic event
split != semantic event
focused Surface != new subject
workspace tab != necessarily a new SessionSpace
```

The workbench may restore and compose these workspaces, but semantic identity remains with the Epi event/subject and native refs established by the parent products.

## 5. Interrelation comes from common reality, not UI coupling

M1–M4 do not become related because one renderer sends ad-hoc messages to another renderer.

They are related because each is a projection of the same underlying informational and computational field:

```text
current event / subject
canonical M / M′ refs
Map-derived relation lineage
QL/kernel operations
source/canon/library state
provider observations
privacy / authority
provenance / readiness
```

A change recognised through one instrument can therefore become available to another through canonical state, refs, Actions and readings.

This is the intended holographic quality: **different native instruments, one governed reality**.

Renderer-local caches, visual selections or body-specific state may exist, but they are not allowed to become a shadow ontology that the other instruments must reverse-engineer.

## 12. Professional-grade means each instrument may have its own body

The system should not chase visual consistency by reducing every deep instrument to React cards.

A professional implementation may legitimately use:

- WebGPU / wgpu / Bevy or another GPU body;
- native audio engine and MIDI/MPE;
- graph/world renderer;
- specialised symbolic editor;
- ordinary document/editor Surface;
- local native application;
- remote material Surface;
- TUI;
- declarative reading when that is genuinely sufficient.

The shared desktop supplies composition and continuity. The instrument supplies the interaction body appropriate to its phenomenon.

The standard is not that every M′ looks alike. The standard is that each feels intentional, responsive, inspectable, source-faithful and mature enough to be used seriously.

## 13. Human and Agent inhabit the same world

Every important deep capability should have one native semantic/action contract usable from both directions.

A human may select, play, drag, type, navigate or manipulate a rich Surface. A canonical Agent must be able to address the same event/subject/ref, inspect the same readiness/provenance and invoke the same canonical Action without parsing the renderer.

The following distinctions remain binding:

```text
visible != Agent-readable
selected != disclosed
addressable != authorised
local != projected
proposal != recognised human source
presentation != semantic identity
```

M4 protected state receives no weaker rule merely because it is richly rendered.

## 14. The old corpus is a feature and meaning mine, not a stack mandate

The historical per-M specs, UX documents, Cycle-3 designs, Theia implementations, graph services, Graphiti integrations, portal-core code, experiments and implementation plans contain large amounts of correct feature intent and computational work.

They failed to yield the intended application largely because implementation repeatedly allowed a provisional substrate or shell to define the product.

The new programme must therefore recursively mine old material with typed provenance:

```text
PRESERVE
    semantic meaning / feature / interaction / computation still wanted

REFINE
    correct intention, but application relation or contract needs sharpening

SUPERSEDE
    old product/host assumption no longer valid

IMPLEMENTATION-EVIDENCE
    proves something exists or worked, but does not define current architecture

RESIDENCY-ONLY
    current/historical package location; not semantic ownership
```

No old package name should appear in a high-level product definition merely because it currently contains useful code.

Conversely, valuable algorithms, interactions, feature detail or acceptance evidence must not be discarded simply because the old shell was wrong.
