# Epi Eightfold Workbench Architecture

## 0. Architectural claim

The eightfold application field remains:

```text
SIX RECURSIVE M′ DEPTHS — 4+2

  epi.deep.m0    M0′ Anuttara
  epi.deep.m1    M1′ Paramaśiva
  epi.deep.m2    M2′ Paraśakti
  epi.deep.m3    M3′ Mahāmāyā
  epi.deep.m4    M4′ Nara
  epi.deep.m5    M5′ Epii

PLUS TWO PARENT 3:3 COMPOSITIONS

  epi.cosmic.123     1 / 2 / 3
  epi.personal.450   4 / 5 / 0
```

The desktop embodiment is intentionally asymmetric:

```text
M0′   implicit ground / source / knowledge / relation dimension

M1′   foreground formal/played instrument
M2′   foreground harmonic/cymatic instrument
M3′   foreground symbolic/clock/transcription instrument
M4′   foreground protected lived/psychoid instrument

M5′   implicit articulation / Agency / pedagogy / recognition / return dimension
```

M0′ and M5′ remain full deep products and can be opened explicitly. Their ordinary role is also to furnish the ground and return conditions through which the other instruments are inhabitable.

This is an application-role asymmetry, not a semantic hierarchy and not a new coordinate system.

## 1. Four layers of state must stay distinct

The corrected architecture uses four practical layers:

```text
1. EPI SEMANTIC STATE
   eventRef
   governed subjectRef / protected Nara relation
   M / M′ coordinate refs
   source / provider / privacy / authority / readiness
   canonical current relations

2. NATIVE PRODUCT / INSTRUMENT STATE
   domain readings
   canonical Actions
   instrument-local operative state
   source-backed body-specific state
   body/provider requirements

3. WORKBENCH CONTEXT
   SessionSpaceRef where current architecture supplies it
   AgentSessionRef
   selected subject / selected child ref
   effective Context
   available Surfaces / Actions

4. PRESENTATION STATE
   tabs / groups / splits
   focused Surface
   camera / zoom / renderer mode
   local panel arrangement
```

The invariants are:

```text
presentation state != semantic event identity
workbench context != semantic event identity
native renderer state != canonical source identity
body/provider residency != semantic ownership
```

A deep instrument can be closed and reopened without creating a second Epi world.

## 3. Workspace tabs and session workspaces

The intended UX permits a person to work with several deep instruments simultaneously.

A **workspace tab/group** is the presentation container for one focused activity or instrument state. It may contain:

```text
surfaceRef
productId
current eventRef / subjectRef co-reference
selected MCoordinateRef
instrument-local presentation state
optional selectedRef
restoration metadata
```

The host may place that Surface in the current tab, a new tab, a split or an alternate native body.

Important distinction:

```text
workspace tab = experienced workspace unit
SessionSpace = current workbench semantic/context object where supplied
```

A tab does not automatically mint a SessionSpace. Several tabs can inhabit one SessionSpace. A provider may legitimately require a distinct session-like object, but that object must come from its native owner rather than being inferred from tab creation.

This permits the experience the product actually needs:

```text
M1 open in one workspace
M3 open beside it
Personal journal in another
M0 cartography opened temporarily
Epii sidecar following the selected native subject
```

while preserving one canonical event/subject field.

1. eightfold remains `4+2 + 2`: six recursive M′ depths plus two parent 3:3 composed worlds;
2. M0 and M5 are full deep products **and** ambient ground/return dimensions of the desktop;

8. multiple deep Surfaces can coexist while co-referring to one event/subject field;
9. inter-instrument relation is through canonical refs/state/kernel/source, not renderer-local coupling;
10. each M′ retains its full source-derived 4+2 internal architecture;
11. historical package/provider refs are implementation evidence, not product definition;
12. heterogeneous native bodies are legitimate and must degrade truthfully;
13. `.0/.5` boundary expression remains domain-specific and executable;
14. returned C/D parent identity is consumed, not reconstructed;
15. human and Agent address the same refs/Actions without screen scraping;
16. selection does not imply disclosure and M4 stays protected;
17. O:I hosts/composes without acquiring Epi semantics;
18. M/S/S′/M′ same-coordinate relation is preserved where relevant without forcing implementation residency;
19. each deep domain receives its own recursive source/UX/implementation refinement before professional-grade completion is claimed;
20. returned implementation or experiential evidence may revise this architecture only through an explicit documented successor.
