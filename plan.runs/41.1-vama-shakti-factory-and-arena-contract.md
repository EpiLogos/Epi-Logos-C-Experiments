## Binding Facts

### VamaShaktiClass

`VamaShaktiClass` is a closed canonical enum per DR-VAMA-6.

```rust
#[repr(u8)]
pub enum VamaShaktiClass {
    Egregore = 0x01,
    Sprite = 0x02,
    Daemon = 0x03,
    Mantra = 0x04,
}
```

Sub-classifier extension is accommodated by enum extension under the owning architecture/spec process, not by replacing this enum with string labels or a parallel taxonomy. Any implementation accepting a raw string must normalize into this enum before identity derivation, arena admission, turn routing, warm persistence, or promotion.

### VamaShaktiSummonRequest

`VamaShaktiSummonRequest` is the only summon envelope admitted by the factory.

```typescript
interface VamaShaktiSummonRequest {
  readonly entity_coordinate: string;
  readonly arena_scene_key: string;
  readonly vama_shakti_class: VamaShaktiClass;
  readonly lifecycle_mode: 'ephemeral' | 'warm' | 'promoted';
  readonly requesting_actor: 'anima_scene_setup' | 'user_direct_cli_warm_admin';
}
```

Field law:

- `entity_coordinate` is required and must resolve through `s5'.gnostic.resolve(coord)` to a `:World` entity node per DR-WORLD-1.
- `arena_scene_key` is required and identifies the Dia-logical Arena scene that receives the summoned voice.
- `vama_shakti_class` is required per DR-VAMA-6 and participates in identity derivation.
- `lifecycle_mode` is one of `ephemeral`, `warm`, or `promoted`.
- `requesting_actor` is limited to [[Anima]] during scene setup or user-direct CLI warm-admin operation.
- `capability_profile` is not a request field. Any submitted capability override is rejected before summon.

### VamaShaktiHandle

`VamaShaktiHandle` is the factory output and the arena-facing identity handle.

```typescript
interface DialogueOnlyCapabilityProfile {
  readonly dialogue_only: true;
  readonly system_tools_granted: never[];
  readonly vault_write: false;
  readonly subagent_dispatch: false;
  readonly terminal_authority: false;
}

interface VamaShaktiHandle {
  readonly vama_shakti_quintessence_hash: Uint8Array; // exactly 32 bytes
  readonly vama_shakti_q_identity: Quaternion;
  readonly vama_shakti_q_composed_at_now: Quaternion;
  readonly vama_shakti_clock_position: number;
  readonly vama_shakti_coordinate: string;
  readonly vama_shakti_class: VamaShaktiClass;
  readonly arena_scene_key: string;
  readonly lifecycle_mode: 'ephemeral' | 'warm' | 'promoted';
  readonly psyche_template_revision: Uint8Array; // exactly 32 bytes
  readonly rupa_specialization_handle: string;
  readonly capability_profile: DialogueOnlyCapabilityProfile;
  readonly summoned_at_ms: number;
  readonly parent_session_key: string;
}
```

Handle law:

- `vama_shakti_quintessence_hash` is the 32-byte BLAKE3 output from DR-VAMA-2 and includes the `vama_shakti_class` byte from DR-VAMA-6.
- `vama_shakti_q_identity` is the stable quaternion identity for the addressed entity/class.
- `vama_shakti_q_composed_at_now` is live composition at summon time.
- `vama_shakti_clock_position` is the cosmic-clock degree used in identity/composition.
- `vama_shakti_coordinate`, `vama_shakti_class`, `arena_scene_key`, and `lifecycle_mode` echo admitted request facts after validation.
- `psyche_template_revision` is the 32-byte BLAKE3 content hash of `psyche.md` at summon time per DR-VAMA-1.
- `rupa_specialization_handle` is opaque; consumers must not infer implementation storage or prompt body from it.
- `capability_profile` is structurally frozen to `dialogue_only: true` per DR-VAMA-5.
- `summoned_at_ms` and `parent_session_key` bind the handle to the session/runtime context that produced it.

### ArenaScene

`ArenaScene` is the scene envelope.

```typescript
interface ArenaScene {
  readonly scene_key: `arena:${string}`;
  readonly pinned_coordinate: string;
  readonly admitted_vama_shaktis: Uint8Array[]; // vama_shakti_quintessence_hash values
  readonly admitted_constitutional: string[];
  readonly user_present: boolean;
  readonly kairos_anchor_at_open: number;
  readonly lifecycle_mode_default: 'ephemeral' | 'warm' | 'promoted';
  readonly cpf_brainstorm_confirmation_token: string;
}
```

Scene law:

- `scene_key` uses `arena:{arc_id}`.
- `pinned_coordinate` is the coordinate anchoring the scene's topic, entity, or ontology-in-conversation arc.
- `admitted_vama_shaktis` stores only `vama_shakti_quintessence_hash` values.
- `admitted_constitutional` records constitutional participants by canonical name; they are not Vama Shaktis and retain their own authority.
- `user_present` is typically true; the user is Trika-0 in the Track 41 scene model.
- `kairos_anchor_at_open` records the opening cosmic-clock/kairotic anchor.
- `lifecycle_mode_default` supplies the scene default for summons that do not further specialize lifecycle.
- `cpf_brainstorm_confirmation_token` records the [[Anima]] brainstorming-done marker required before scene admission when CPF starts at `(00/00)`.

### ArenaTurn

`ArenaTurn` is the per-turn routing envelope.

```typescript
interface ArenaTurn {
  readonly turn_index: number;
  readonly turn_speaker_handle: VamaShaktiHandle | 'user' | `constitutional:${string}`;
  readonly turn_address: string;
  readonly turn_kairos_delta: unknown;
  readonly turn_arrived_at_ms: number;
}
```

Turn law:

- `turn_index` is monotonically increasing within a scene.
- `turn_speaker_handle` is one of a `VamaShaktiHandle`, `user`, or `constitutional:{name}`.
- `turn_address` carries the routing address for the turn.
- `turn_kairos_delta` carries the live kairotic delta used by classifier-aware turn routing.
- `turn_arrived_at_ms` records arrival time for ordering and replay.

### ArenaDialogueLine

`ArenaDialogueLine` is the dialogue-line metadata envelope. The dialogue body itself remains behind an opaque handle.

```typescript
interface ArenaDialogueLine {
  readonly turn_index: number;
  readonly dialogue_body_handle: string;
  readonly vak_address: VakAddress;
  readonly l5_lens_witness: string;
  readonly cited_coordinates: string[];
}
```

Dialogue-line law:

- `turn_index` references the `ArenaTurn` in which the line occurred.
- `dialogue_body_handle` is opaque; implementation must not expose raw dialogue outside the protected local surface.
- `vak_address` is the DR-VAK-7 C' expression for the line.
- `l5_lens_witness` is the L5' + T/T' wikilink-accretion handle for the line.
- `cited_coordinates` contains coordinate references cited or activated by the line.

## Refusal Law

The summon factory and every route that wraps it must refuse these requests before handle creation:

- `entity_coordinate` does not resolve to a `:World` entity node: refused per DR-VAMA-3. The refusal hint must point at `hen_entity_candidate_propose` as the path to create the wanted entity Form before summon.
- `requesting_actor` is not `anima_scene_setup` or `user_direct_cli_warm_admin`: refused as unauthorized.
- Request attempts to set, widen, relax, or otherwise override `capability_profile`: refused per DR-VAMA-5.
- `vama_shakti_class` is missing or not one of `Egregore`, `Sprite`, `Daemon`, or `Mantra`: refused per DR-VAMA-6.

Refusals are terminal for the summon attempt and must not allocate a `vama_shakti_quintessence_hash`, register arena presence, update warm persistence, or emit dialogue-line metadata.
