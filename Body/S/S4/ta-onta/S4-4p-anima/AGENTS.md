# AGENTS.md — S4-4p-anima

## Purpose
The Anima ta-onta carrier (S4-4' class): the agent-orchestration & meta-dispatch extension — VAK evaluation, CF dispatch, CFP thread execution, and CS-phase management for the PI agent runtime.
Canon: [[ARCHITECTURE-DIAGRAM-PACK]] -> [[S4-SPEC]] / [[S4-ARCHITECTURE]] (see also [[S-SYSTEM-INDEX]]).

## Ownership

- `extension.ts` — source-contract facade + entrypoint; re-exports the runtime under `./extension/`
- `extension/` — runtime: `mod.ts`, `tools.ts` (aggregator: vak_evaluate + goal_prelude, then registers the split families per 17.T17.10), `dispatch-tools.ts` (the six-tool dispatch family: anima_orchestrate, anima_arena_orchestrate, dispatch_parallel_agents, dispatch_fusion_agents, dispatch_moirai_night_pass, anima_self_invoke + arena/Mercurius helpers), `nous-disclose.ts` (isolated nous_disclose S0'/S1'/S2' dis-closure tool), `dispatch.ts` (incl. the 46.1 [[Z-thread]] runtime primitive: `registerZThreadShape`/`dispatchZThread` composing ≥2 distinct CFP moves under one autonomous envelope, closed only by the 12.35 Verify gate via `evaluateVerifyGate`; state queryable via `getZThreadSnapshot`/`listZThreadSnapshots`), `capabilities.ts` (Pleroma capability-matrix reader; derives a constitutional CF team only from its `cf_team_composition_gates` and `constitutional_ct_mapping`), `subscriptions.ts`. `dispatch.ts` also carries the **score lifecycle** (50.T50.07): `CSState` gained an `origination` polarity that is defaulted on BOTH read and write, so every session starts `(00/00)` dialogical — the existing `before_agent_start` reset in `subscriptions.ts` lands there without naming it, and no reader can see a session with no origination. `persistScore()` REFUSES a session that is no longer originating (a score comes from dialogue; "the flow I was already mechanically running" is not an origination), `assertScoredOrchestration()` validates the shape on the way OUT of storage because a score is loaded in order to be EXECUTED, and `rerunScore()` sets the session mechanistic for the duration then restores the prior polarity — a re-run does not re-originate, and re-running mid-dialogue does not end the dialogue. Its runner is INJECTED rather than imported, because `lib/vak-orchestration-surface.ts` and this module share the `lib/thread-shape.ts` surface and importing the surface back would close a cycle. Persistence itself is Hen's (`S4-1p-hen/modules/score-store.ts`). It also carries the **learned-from-review** half of the checkpoint law (50.T50.09): `recordCheckpointReview()` appends a review's verdict about whether a run wanted a human checkpoint into the score's own append-only run log, and `learnedCheckpointProposals()` reads the affirmative ones back for a later author. Both directions are deliberately inert — a proposal is EVIDENCE a script author may adopt by writing `reason: "learned-from-review"` onto a step by hand, and `checkpointGate` never reads this store. That gap IS the no-auto-insertion policy, structural rather than promised.
- `lib/` — pure reusable Anima orchestration helpers; `thread-shape.ts` holds the **threads-are-shapes / tools-are-capabilities** model (`shapeOf`, `capabilitiesFor`, `TOOL_CAPABILITIES`); `arena-orchestrator.ts` holds classifier-aware arena turn routing, Mercurius kairos state, CPF-gate, and dispatch-plan policy; `child-pi-executor.ts` (50.T50.02) is **THE single choke point where a dispatch decision becomes a child pi process** — the three former `spawn("pi", …)` copies in `S4/{agent-team,agent-chain,pi-pi}.ts` all route through `dispatchChildPi()`, which applies every invariant once: Pi→subagent only (`CHILD_PI_BINARY`, not injectable), the `--tools` allow-list via `resolveEntitlement()` (agent-chain and pi-pi previously passed raw frontmatter tool strings with NO gate), `guardVamaShaktiDispatch` (DR-VAMA-5), `enforceReviewGate` (12.T12.4), and — since 50.T50.09 — the **CPF checkpoint** (`checkpointGate`): a dispatch carrying an authored `(00/00)` checkpoint that no human has answered refuses with `child-pi/cpf-checkpoint-unsatisfied` BEFORE a process exists. Gating here rather than only in the script surface is what makes a checkpoint unbypassable — a dispatch can reach a child through agent-team/agent-chain/pi-pi without ever passing through an orchestration. A checkpoint the human has answered is handed to `enforceReviewGate` ONLY when it was authored `validates: "review"` — a dispatch-scoped answer does not discharge the 12.T12.4 verdict gate — and when a halting checkpoint also gates a review, the refusal discloses the pending decision and actor, because a human cannot final-validate a verdict they were never shown. A violated invariant throws `ChildPiDispatchRefused` and no process is spawned. `childPiRuntimeArgs()` remains the runtime-arg source, now called only here. `orchestration-run.ts` (50.T50.05) holds **Anima's own run state** — the top-level script and its context live in the parent, opened on `session_start` and cleared on `session_shutdown` by `extension/mod.ts`. Its load-bearing property is CONTEXT ISOLATION: `childInputFor()` passes ONLY a step's declared imports to a child (a step declaring nothing receives nothing — isolation is the default), `completeStep()` refuses an undeclared or missing export, and a child's raw output is measured then DROPPED rather than accumulated, so the parent's context stays flat in the number of children. This is the second half of the token win: 50.T50.01 removed the per-hop re-send inside one agent's work, this removes transcript-passing BETWEEN agents. `vak-orchestration-surface.ts` (50.T50.03) is the **typed six-coordinate scripting surface** an Anima orchestration is written against — each of CPF/CT/CP/CF/CFP/CS is a composable AXIS with its own reader (`reviewPolarity`/`haltsForHuman`, `artifactTemplates`, `framePosition(Index)`, `boundAgent` via [[AGENT_CF]], `executionShape`/`primitiveFor` via `conventionalToolFor` (a CONVENTION, not an identity — `null` for CFP4), `sequence`/`isNightPass`), plus `defineOrchestration`/`runOrchestration` (CS orders the run: Day before Night′, then CP position) and the load-bearing envelope invariant: `emit()` is the ONLY emission constructor and `assertFullEnvelope`/`describeEnvelopeViolations` refuse a partial or non-canonical address naming the offending coordinate. Types are NOT redefined — it consumes `ta-onta/shared/vak_address.ts`, the one TS mirror. It also carries the **CP nesting evaluator** (50.T50.04): a position inside a context frame is either a terminal `FrameLeaf` dispatch or a `FrameNest` opening a whole nested frame — the `.`-nesting operator surfaced through CP, as plain recursion. `frameSlots()` derives a frame's internal positions from its OWN notation (`(4.0/1-4.4/5)` is the one range form, expanding to the canonical `CP4.0..CP4.5` set); `expectedCpForSlot()` + `assertFrameNesting()` enforce that a child of the 4.x parent carries the CP of the slot it occupies, so CP genuinely PLACES the step; `runNestedFrame()` recurses, dispatching at leaves only (frames contribute structure, never a dispatch) and returning a trace whose `depth`/`framePath`/`slotPath` record the nesting for later replay and scoring. Since 50.T50.09 an `OrchestrationStep`/`FrameLeaf` may also carry the agent-authored `checkpoint` (`CpfCheckpoint`), validated at DECLARATION time by `checkpointAuthoringGate` — reason and polarity are checkable when the script is written, whether a human answered is not, so the two halves of the law are checked at the two different moments they become answerable. `DialogicalHaltRequired` carries the authored `reason`, so a halt says why a human is standing there and not merely that one is.
- `modules/` — per-agent dispatch/route/hook units (nous-clearing, logos-scope, eros-route, mythos-pattern, `symbolic-protein-reader.ts` for protected-handle Mythos reading/history/close binding, psyche-continuity with renderer-state carry-forward for review blocks, reading-frame-evaluator, sophia-hook/synthesis, aphoristic-skill, moirai-dispatch, judge-role, `dispatch-policy.ts` which emits Pleroma-consumable `tmux_topology_decision` envelopes from selected VAK/Elo dispatches, `parent-slice.ts` which redacts a [[ConversationSliceHandle]] into the same child environment for headless tmux and visible cmux projections and publishes successful child c=1/c=0 completion to Chronos, skill-registry, anima-invoke-payload; `dispatch-validate.ts` carries both the CF/agent binding law and — since 50.T50.09 — the **CPF checkpoint gate**: `CHECKPOINT_REASONS` is the CLOSED set of three things an authored checkpoint can be grounded in (`implied-by-task` / `requested-at-origination` / `learned-from-review`), a fourth is refused rather than accepted as free text, and `checkpointGate` holds an authored checkpoint until `respondedBy: "human"` — an agent answering its own gate is not an answer. **There is no auto-insertion policy, and its absence is structural:** a checkpoint exists only because it was authored onto a step, `(00/00)` alone stays the Ouroboros / open-conversation register the `CPF_DIALOGICAL` docblock describes, and nothing in the gate reads the score store. ## Local Contracts
- `CONTRACT.md` (Anima Contract — Agent Orchestration & Meta-Dispatch)
- Source-contract facade: `extension.ts` (preserves the active-tool list inspected by S0 tests)
- Owning spec: [[S4-SPEC]] / [[S4-ARCHITECTURE]]
- **CFP does NOT name a tool — threads are shapes, tools are capabilities.** Canon maps a CFP to a *skill or pattern* (`S4'/skills/vak-coordinate-frame/SKILL.md`: CFP1 → `dispatching-parallel-agents`, CFP4 → `executing-plans`) and writes CFP3 as a **mode of** CFP1's skill — many-to-one, in the constitutional table itself. The old `zThreadToolForMove` bijection was an invention of the code, and it failed on its own terms: CFP4 dangled because "Long" is a duration/completion property with no dispatch primitive to point at. `lib/thread-shape.ts` now carries `shapeOf(cfp)` (fan-out / aggregation / nesting / autonomy / completion) and `TOOL_CAPABILITIES` keyed by TOOL, with `capabilitiesFor(shape, entitled?)` answering "which entitled tools could realise this" — advisory and many-to-many, never "which tool IS this thread". `conventionalToolFor("CFP4")` is `null`, which is the honest answer. `tilldone` is a completion DISCIPLINE (it realises `completion-gate` and nothing else) available to any shape declaring `completion: "till-done"` — which is why it is also entitled to `anuttara`, an agent with no CFP4 relationship.
