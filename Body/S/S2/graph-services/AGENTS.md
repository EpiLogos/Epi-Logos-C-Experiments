- Track 54 T54.01 — `src/txlog_forensics/` (feature `txlog-forensics`, **off by default**, so it never links into a serving build): a Neo4j 5.26 transaction-log decoder built for the 2026-07-28 `DETACH DELETE` recovery. Walks `neostore.transaction.db.0` and emits a typed command stream (`Command::{Node,Property,Relationship,RelationshipGroup,*Token,*Counts,GroupDegree,SchemaRule}`) carrying **both** record images — the before-images are the only surviving copy of what the wipe destroyed, since the store pages were reclaimed. `cursor.rs` (checked little-endian reads), `record.rs` (record images; field order and flag bits transcribed from Neo4j's own `LogCommandSerializationV5_0`/`V4_2`/`V4_3_D3`, read out of the shipped jar), `value.rs` (property values: inline scalars, inline short strings, inline packed arrays, spilled `DynamicArrayStore` arrays, and `DynamicRecord` chains — element widths stay distinct, so `float[]`/`double[]` and `int[]`/`long[]` are never conflated), `codec_tables.rs` (**generated** — the SHORT_STRING codec tables are extracted from `org.neo4j.internal.codec.ShortStringCodec` by reflection, not reproduced by hand; do not edit). Type 22–27 commands carry only one image: **Created** puts the read record in *after*, **Deleted** in *before* — inverting that inverts the recovery. The decoder is deliberately strict: an unknown command type, property type, or short-string encoding is an ERROR, never a skipped record, because a decoder that silently drops what it does not understand yields a plausible but quietly incomplete recovery. Does NOT own reconstruction or apply (T54.02/T54.03). Verified three ways, all against Neo4j's own decoders rather than this decoder's own output: exact census agreement with `LogEntryReader` over the real 118 MB log (854,078 entries, 60,190 transactions, every per-command-type count), plus two golden suites under `tests/fixtures/` — `txlog_array_goldens.tsv` (real payloads vs `DynamicArrayStore.getRightArray`/`ShortArray.decode`) and `txlog_inline_label_fields.tsv` (every distinct `labelField` in the log vs `InlineNodeLabels`). Both golden suites run in the normal crate suite; only the 118 MB real-log suite is `--ignored`.
- Track 54 T54.02 — `src/txlog_forensics/replay.rs` replays the decoded stream into an in-memory store and materialises each node's property map at a chosen instant (stop point: the transaction immediately before the mass delete, located by its size — tx 59354, 2,098 node deletions). **Attribution is by property-record owner, never by walking `node.next_prop`.** The chain walk is the textbook traversal and is wrong here: measured on the real log it reached 8,307 of 31,008 owned records, produced no `S3` node at all, and cross-attributed relationship source/target coordinates onto node records. Owner attribution is exact — 2,099 coordinate-bearing nodes resolve to 2,099 distinct coordinates 1:1, matching the 2,098 the wipe deleted, and `M2-3` resolves to node 432, the id Neo4j's own reader independently reported. Recovers **properties only**: `cypher_literal` emits additive `SET n +=`, never a MERGE, and returns `None` for values the decoder does not interpret so an undecoded `TEMPORAL` is skipped rather than guessed. Artifacts + applied results are recorded in `Idea/Bimba/Map/datasets/recovery/README.md`.
- CCT-17b (16.T16.17): `src/retrieval/wikilink_index.rs` promotes wikilinks from presentation to retrieval primitive (`suggest_world_links_by_coordinate` over World/Types entity files — coordinate-literal targets resolve directly, named targets resolve through sibling entities, spans carry the `c_1_source_artifact_span` pointer shape, unresolvable targets are never invented); `src/retrieval/tri_layer.rs` is the MemoryGraphRAG three-layer composition (ontology-filter → fact-traverse → cosine-rank; ranking never resurrects a filtered passage, facts need span anchors) — the `s5'.gnostic.query_with_layers` endpoint registration is Track 12's landing.
