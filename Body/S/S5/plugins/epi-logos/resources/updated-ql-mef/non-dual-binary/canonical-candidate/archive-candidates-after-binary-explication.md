# Archive Candidates After the Binary Explication — Full Resources Audit (Proposal Only)

**Date:** 2026-06-10 (revised — scope expanded from the non-dual-binary tree to the entire `resources/` directory, 94 files)
**Status:** Proposal. Nothing listed here has been archived, moved, or deleted. No action should be taken until the canonical-candidate set is reviewed and promoted, and a human has confirmed each row flagged for review.

**Principles applied (conservative by instruction):**

- Skills, plugin manifests, coordinate-system files, executable resources, and active canon files default to **do-not-archive**.
- A file is an archive candidate only when its content is demonstrably incorporated into the canonical-candidate set AND it is not referenced by skills, plans, or canon as a living authority.
- "Incorporated" does not mean "safe to remove" — it means the content survives elsewhere; the witness value of the original may still justify keeping it.
- Most of `resources/` is **infrastructure of a different stratum** — runtime canon, pedagogy, methods, research reservoirs — that the Binary Explication draws on but was never meant to absorb. Such files are *represented* in the candidate set (their architecture, standards, and findings inform it) without being *sublimated* into it, and they remain living. The table distinguishes these cases explicitly.
- All archive recommendations are contingent on promotion. Before promotion, every row defaults to **keep**.
